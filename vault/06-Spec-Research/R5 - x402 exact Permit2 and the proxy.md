# R5 - x402 exact Permit2 and the proxy

**Part of:** [[06-Spec-Research/01 - Spec Research]]
**Source:** `test/SettlementSplitOnBsc.fork.t.sol:158` · `contracts/interfaces/IX402ExactPermit2Proxy.sol:27`

**Summary:** The facts about the paid rail that were **read off the deployment**, not copied from a document: how the canonical `x402ExactPermit2Proxy` and Permit2 were identified as what they claim to be, the two EIP-712 domains that must not be interchanged, the `Witness{to, validAfter}` struct that lets an untrusted broadcaster settle a payment, and why `settleWithPermit` means the paying client sends **zero** transactions. It also records the boundary of the evidence: this proves the rail works when *we* are the facilitator and *we* are the payer's counterparty. Nothing here proves a third party has ever paid.

**Key points:**
- **"Code exists at that address" is far too weak**, and this is the check that replaced it (`test/SettlementSplitOnBsc.fork.t.sol:158-166`): bytecode present at both addresses (`:159-160`); `proxy.PERMIT2()` returns `0x000000000022D473030F116dDEE9F6B43aC78BA3` (`:161`); `proxy.WITNESS_TYPEHASH()` equals `keccak256("Witness(address to,uint256 validAfter)")` (`:162`); `proxy.WITNESS_TYPE_STRING()` equals the `exact` witness tail (`:163-166`). The three getters are declared in our mirror at `contracts/interfaces/IX402ExactPermit2Proxy.sol:44-46` precisely so they can be called.
- The digest is built with the **contract's own constant**, not our transcription: `_witnessHash()` calls `proxy.WITNESS_TYPEHASH()` (`test/SettlementSplitOnBsc.fork.t.sol:95-97`). If the deployment changed its witness shape, the fork test fails — a document could not tell us that.
- Addresses, both **not ours**: Permit2 `0x000000000022D473030F116dDEE9F6B43aC78BA3` and proxy `0x402085c248EeA27D92E8b30b2C58ed07f9E20001` (`test/SettlementSplitOnBsc.fork.t.sol:33-34`), repeated as constants in `script/PaidVerificationDemo.s.sol:39-40` and `signer/src/x402.js:22-23` so the script and the server cannot quietly point somewhere else.
- **Two EIP-712 domains are signed in one settlement and they are not the same shape.** Permit2's is `EIP712Domain(string name,uint256 chainId,address verifyingContract)` — **no `version` field** (`test/SettlementSplitOnBsc.fork.t.sol:39-40`, assembled at `:92`, and in the client at `signer/src/x402.js:27`). The ERC-20Permit token's domain **has** `version: "1"` (`signer/src/x402.js:28`) because OpenZeppelin's constructor is `constructor(string memory name) EIP712(name, "1") {}` (`node_modules/@openzeppelin/contracts/token/ERC20/extensions/ERC20Permit.sol:39`). The two are written separately on purpose and swapping them is stated in the file header (`signer/src/x402.js:8-11`): the result is a well-formed signature the contract refuses.
- **The witness is `Witness(address to, uint256 validAfter)`** (`contracts/interfaces/IX402ExactPermit2Proxy.sol:27-30`). The type *name* must be exactly `Witness` because Permit2 weaves the type name into the typehash (`signer/src/x402.js:45`). `to` is what makes the broadcaster untrustworthy-safe: `test_fork_witness_dengan_tujuan_berbeda_gagal_ditandatangani` (`test/SettlementSplitOnBsc.fork.t.sol:245`) signs for `to: split`, calls with `to: attacker`, and the settlement reverts with nothing entering the contract.
- **`settleWithPermit` is why the client sends zero transactions.** `settle(...)` (`contracts/interfaces/IX402ExactPermit2Proxy.sol:50`) presumes the client already approved Permit2 — the flow the test at `:175` sets up with an explicit `token.approve(PERMIT2, …)`, which itself costs BNB. `settleWithPermit(...)` (`:56-62`) performs the EIP-2612 permit **and** moves the funds in one call, so the payer never needs an approval transaction and never needs BNB. Proven end-to-end by `test_fork_klien_nol_gas_sampai_dana_terbagi` (`:267`), which starts at `allowance(payer, PERMIT2) == 0`, records the payer's transaction nonce, settles, requires the nonce unchanged, and then follows the money to 900 / 100 (`:268-296`). The same assertion is required in the broadcast script: `require(vm.getNonce(s.client) == nonceBefore, …)` (`script/PaidVerificationDemo.s.sol:123`).
- **`accepts[]` is the scheme's shape as an x402 client reads it, not a shape we invented** (`signer/src/x402.js:60-77`): `scheme: 'exact'`, `network: eip155:<chainId>`, `maxAmountRequired` as a **string**, `resource`, `description`, `mimeType`, `payTo`, `paymentTimeout`, `maxTimeoutSeconds`, `asset`, `extra: {name, version}`. `payTo` is the split contract, never a platform EOA.
- Both entry points are matched by **argument-less events** `Settled()` / `SettledWithPermit()` (`contracts/interfaces/IX402ExactPermit2Proxy.sol:64-65`), so the tests select them by `topic0` (`test/SettlementSplitOnBsc.fork.t.sol:46-47`, `_emitted()` at `:146`) — there is nothing to decode and no excuse for a loose match.

**Detail:**
- **Mirror, not copy.** The interface file is hand-written because the x402 libraries do not compile in this rig and the contracts we call are not ours (`contracts/interfaces/IX402ExactPermit2Proxy.sol:4-12`). The same file says what happens when the mirror is wrong: `settle()` reverts or ABI decoding fails — the error is loud, not silent. Struct field order is part of the encoding: `TokenPermissions(address token, uint256 amount)` (`:14-17`), `PermitTransferFrom(TokenPermissions permitted, uint256 nonce, uint256 deadline)` (`:19-23`), `EIP2612Permit{uint256 value; uint256 deadline; bytes32 r; bytes32 s; uint8 v}` mirroring `x402BasePermit2Proxy` (`:32-40`).
- **`v` is chain-safe (27/28), not y-parity** — decoded and corrected in exactly one place (`signer/src/x402.js:119-127`).
- **The token nonce must be read from the contract** (`nonces(owner)`, `signer/scripts/x402-check.js:108`); reusing `0` makes the *second* payment fail with a cause far from the fix (`signer/src/x402.js:77-79`).
- Domain separation is verified rather than assumed even inside the test: the token permit is signed under `token.DOMAIN_SEPARATOR()` with `token.nonces(payer)`, both read from the contract (`test/SettlementSplitOnBsc.fork.t.sol:128-130`).
- **Run it:** `forge test --match-contract SettlementSplitOnBscForkTest -vv --evm-version cancun --fork-url https://bsc-testnet.publicnode.com` (`test/SettlementSplitOnBsc.fork.t.sol:27-29`). Without `--evm-version cancun` the run dies with `[NotActivated]` → [[R6 - Toolchain traps that cost time]]; without `--fork-url` every test in the file is **skipped**, not passed (`vm.skip` at `:71-73`) — 7 of the 97 in [[09-Testing/00 - Hub Testing]] come from this file.
- 🔴 **What remains unproven, and must travel with any paid-path sentence.**
  1. **We are the facilitator.** `settleWithPermit` is facilitator work, so in this demo *our* server pays the gas for the settlement and the split (`signer/src/x402.js:13-16`); in production that is a third party whose economics this repository has not tested.
  2. **The asset is a demo coin.** `DemoCourseToken` has an open, unauthenticated `mint()` (`contracts/DemoCourseToken.sol:30-32`), so no revenue, price or scarcity claim can rest on it — only the fact that value moved and divided.
  3. **There is no outside payer.** The demo payer's key is derived from a constant string (`signer/scripts/x402-check.js:57`, `script/PaidVerificationDemo.s.sol:78`), so every green run on this path is us paying us. `README.md:64-67` records the same limit.
  The honest sentence is the handshake: `402` → sign → settle → split → serve → `X-PAYMENT-RESPONSE`, with the shares read back from chain.
- **Do not call the deployed fee rate a spec fact.** The price and the bps are configuration of this repository (`signer/src/server.js:39`, `script/PaidVerificationDemo.s.sol:42` and `:44`); the protocol defines only the message shapes above.
